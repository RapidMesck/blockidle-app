# Frame-Rate Pacing via `requestAnimationFrame` Interception and `visibilitychange` Suppression

In `blockidle.io/play` (`js/main.js`), the 3D WebGL loop is driven by recursive `window.requestAnimationFrame(quadro)` calls, while `visibilitychange` (`document.hidden = true`) triggers `POST /api/visivel { v: false }` which exits free-roam mode and forces a full scene reload and offline summary modal upon returning. Furthermore, the game's built-in `bi-graficos = 'leve'` option couples a 30 FPS limit with reduced pixel ratio and disabled shadows. Therefore, the Client Shell controls frame pacing by wrapping `window.requestAnimationFrame` in the WebView initialization script (supporting presets `15 / 30 / 60 / 120 / 144 / 240 / Unlimited` in foreground and `0 / 5 / 15 / 30 / 60` in background) independently of graphics settings, and suppresses `visibilitychange` / overrides `document.hidden` when **Keep Awake** is enabled so background/tray execution keeps the live SSE session intact.
